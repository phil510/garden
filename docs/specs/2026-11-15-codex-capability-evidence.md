# Codex adapter capability evidence

This records the evidence for [issue #401](https://github.com/phil510/garden/issues/401) on 2026-11-15. It supports implementation, but does not complete the issue's authenticated live-test acceptance criteria.

The installed CLI is **0.169.0**. Source inspection used OpenAI's matching `rust-v0.169.0` tag, commit `d32063f96c2dff1dc96af839b3952abb6acfeda4`. Earlier 0.157.0 observations are historical evidence.

## Implementation consequences

Launch each Codex session with its process-local hook overlay. On 0.169.0, `-c hooks.*` selects an embedded app server rather than the shared daemon. The hook runtime snapshots its server process's environment, so the pane's `GARDEN_*` variables reach hooks through that embedded server. A shared daemon snapshots its own environment.

For bound sessions, use `codex queue --thread <codex-id> --message <text>` without the spawn command's hook overrides, `--no-daemon` or `--resume`. Queue writes shared durable storage, and an embedded owner observes external changes on a ten-second polling interval. Queue success means durably queued, not processed by the model.

Keep the pending-session tmux first-prompt fallback: another server cannot queue to a conversation before its rollout materializes. Handle same-id resume and compact bindings idempotently; clear and fork represent a new conversation. SessionStart must not override a working status with waiting.

## Tested with the installed binary

Probes used fresh temporary HOME and CODEX_HOME directories, an isolated environment and no copied credentials. They did not change live user settings, Claude processes or Garden instances. The probe app servers and isolated queue daemon were stopped afterward.

- CLI help confirmed the version and supported queue, resume, hook-trust and daemon flags.
- An isolated app server accepted `-c 'hooks.SessionStart=[{hooks=[{type="command",command="/usr/bin/true"}]}]'`. `hooks/list` reported an enabled `sessionFlags` hook with `trustStatus=untrusted`. No trust was granted.
- A new root thread returned equal thread and session ids. Its `historyMode=paginated` still produced an ordinary JSONL rollout after the first turn.
- Queueing before that first turn failed with `no rollout found for thread id`.
- After a first turn began in process A, process B's plain queue command returned exit zero and a queued-submission id. A received `thread/queue/changed` approximately ten seconds later. A owned the loaded thread; B used the isolated shared daemon.
- The model request returned 401 because the temporary home had no authentication. The first turn was still retrying when the queue change arrived. This establishes cross-process queue observation, not successful inference, queued-turn completion or interactive TUI behavior.

## Hook configuration and permissions

A minimal supported overlay is `hooks.SessionStart=[{hooks=[{type="command",command="...",timeout=1}]}]`. Event keys are PascalCase; timeout is in seconds. There is no command-handler `env` field: pass Garden's instance identity through the child process environment. The [shared hook schema](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/protocol/src/hooks.rs#L140) is the source of truth.

Hook trust and tool permissions are separate. `--dangerously-bypass-hook-trust` permits enabled hooks for that invocation; it does not disable the sandbox or tool approval. The hook's `permission_mode` is derived from approval policy alone: `never` becomes `bypassPermissions`, while other policies become `default`. That payload does not establish whether the sandbox is disabled. See the [permission-mode mapping](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/hook_runtime.rs#L1076).

## Remaining authenticated smoke tests

Issue #401's five acceptance criteria are **not complete** from this evidence. The source contracts and no-auth probe support implementation, while these remain for a human-authorized authenticated isolated smoke run:

- Successful TUI first turn, resume and compact; record hook payload and id/path before/after. Current resume source differs from the old 0.157 failed-turn observation: implement idempotent resume handling now.
- Queue a message into a live tmux TUI, observe the queued turn finish, and verify busy/idle ordering. The isolated probe observed queue change, not completed inference.
- Cause an actual approval under on-request sandboxing, observe PermissionRequest and status recovery after response. Bypass mode will not exercise this.
- Two panes with distinct GARDEN_SESSION_ID values, process overlays and captured hook payloads. Source says embedded launch keeps pane env; a shared daemon itself snapshots daemon env.
- Hook-trust bypass's full plugin/project trust persistence side effects on 0.169 were not reproduced here; do not equate earlier 0.157 observations with a fresh test.

The plain queue plus embedded overlay design has direct source support and an isolated cross-process observation. Issue #401 remains incomplete until its authenticated acceptance criteria have been observed.
